=== bag, ref und create

==== bag — BAG OF STRUCTURE

[source,ilimap]
----
bag adressen {
  from a in src class "Source.Adresse" where a.PersonId == p.OID;
  target Adressen;
  structure "Target.Adresse";
  mode embed;
  maxItems 5;
  parentRef attribute "PersonId" parent p;

  assign {
    Strasse = a.Strasse;
    PLZ = a.PLZ;
    Ort = a.Ort;
  }

  bag dokumente {     // verschachtelter Bag
    ...
  }
}
----

[cols="1,1,1,3",options="header"]
|===
| Feld | Typ | Pflicht | Beschreibung
| `from` | block | ja | Quelle für Bag-Einträge (alias, inputId, class, where)
| `target` | identifier | nein | Zielattributname (Default: Bag-Name)
| `structure` | string | ja | Strukturklasse für Bag-Einträge
| `mode` | enum | nein | `embed` (Default) oder `expand`
| `maxItems` | number | nein | Maximale Anzahl Einträge
| `parentRef` | block | nein | Rückwärts-Referenz zum Parent (attribute oder role)
| `where` | expression | nein | Zusätzliche Filterbedingung
| `assign` | block | nein | Attributzuweisungen für die Struktur
| `bag` | block | nein | Verschachtelte Bags (rekursiv)
|===

==== ref — Referenz-Mapping

[source,ilimap]
----
ref gebaeude_ref {
  association "Target.GebaeudeRef";
  role "Gebaeude";
  required;
  target rule gebaeude_rule sourceRef s.GebaeudeRef;
}
----

[cols="1,1,1,3",options="header"]
|===
| Feld | Typ | Pflicht | Beschreibung
| `association` | string | nein | Qualifizierter Assoziationsname
| `role` | string | nein | Rollenname
| `required` | flag | nein | Referenz ist zwingend
| `target` | block | ja | Ziel: `rule <id> sourceRef <expression>`
|===

[NOTE]
====
Referenzen werden über den `sourceRef`-Ausdruck aufgelöst. Ein Alias wie `s` verweist auf das gebundene Quellobjekt. Ein Pfad wie `s.ParentRef` liefert den vollständigen Referenzwert. `oid(s)` und `refOid(s.ParentRef)` liefern OIDs als Text.

Eine lokale Referenz gilt im Basket des Quellobjekts. Eine explizite Quell-BID bestimmt den referenzierten Basket. Die Zielregel kann den Input eingrenzen. Mehrdeutige Treffer und fehlende Pflichtreferenzen führen zu einem Fehler.
Externe Referenzen zwischen Baskets werden in XTF 2.4 über die Transfer-ID innerhalb derselben Ausgabe kodiert. Die Zielrolle muss `EXTERNAL` erlauben. Für XTF 2.3 schlägt die Ausgabe dieses Falls fehl, weil der eingesetzte IOX-Writer `REF` mit `BID` nicht korrekt kodiert.

Bei einer Komposition muss die Referenz in der Regel des abhängigen Child-Objekts auf dessen Parent-Rolle zeigen. `oid(s)` liefert dort weiterhin nur die OID des Child-Objekts und nicht automatisch die OID des Parents.
Zeigt die Zielrolle auf eine abstrakte Basisklasse, darf die Zielregel eine konkrete Unterklasse erzeugen. Die Referenzauflösung berücksichtigt die INTERLIS-Vererbung; unverwandte Zielklassen werden weiterhin als Typfehler abgewiesen.
====

Selbständig übertragene binäre Assoziationen werden in XTF durch eine explizite
Regel mit Assoziationsnamen in `source` und `target` migriert. Für jede der
beiden Rollen gibt es einen `ref`-Block. Fachattribute verwenden `assign`.
Links mit eigener OID folgen der OID-Strategie. Links ohne eigene OID haben
keine TID. Eingebettete Rollen werden am Besitzer gemappt.

Für direkte `REFERENCE TO`-Klassenattribute bezeichnet `ref` den
Zielattributnamen. `sourceRef` liest das Quellattribut als Referenzwert. Der
Resolver verwendet Modellziel, `EXTERNAL` und die Ziel-OID der erzeugenden Regel.
Das gilt auch für geerbte Attribute und Typaliase. Assoziationsvererbung,
mehr als zwei Rollen, geordnete Rollen, Rollen mit alternativen oder
eingeschränkten Zielen sowie Referenzen in verschachtelten Strukturen
liegen ausserhalb dieses Funktionsumfangs.

==== create — Zusätzliche Zielobjekte

[source,ilimap]
----
create class "Target.Metadaten" {
  assign {
    Quelle = "ilitransformer";
    Timestamp = now();
  }
}
----

[NOTE]
====
`create` ist experimentell. Es erzeugt zusätzliche Zielobjekte unabhängig von der 1:1-Quellabbildung.
====
